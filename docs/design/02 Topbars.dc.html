LAYERS 02 · Topbar — trois variantes
Palette

Linux — Hyprland / Wayland

décoration côté client · réserve 0 / 0
Aucune décoration système : le compositeur ne dessine ni barre de titre ni boutons, l'app les dessine elle-même. Sous Hyprland en tuilé, les trois boutons sont masqués (le compositeur gère fermeture et taille au clavier) ; sur un bureau classique — GNOME, KDE, XFCE, ou Hyprland en fenêtre flottante — ils apparaissent à droite. L'app lit gtk-decoration-layout pour connaître l'ordre et le jeu de boutons attendus, et respecte le côté (droite par défaut, gauche sur une session configurée ainsi).

Deux sous-variantes, une seule mise en page
Tuilé (Hyprland) : réserve droite 0. Bureau classique ou fenêtre flottante : réserve droite 115px, soit 3 × 38 plus le séparateur 1px. Bascule « Boutons Linux » en haut à droite. La réserve est un spacer flex, donc rien d'autre ne bouge.
Boutons dessinés, pas empruntés
Glyphes linéaires 16px trait 1.5px sur la grille de l'app, angles droits, 38×48 chacun. Ni cercles macOS ni Segoe Fluent : la fenêtre reste une fenêtre LAYERS.
Survol et ordre
Minimiser et agrandir prennent surface_raised, fermer prend danger plein — comme sur Windows. L'ordre et le côté suivent gtk-decoration-layout.

macOS

titlebar masquée, feux incrustés · réserve 78 / 0
Les feux tricolores sont dessinés par le système par-dessus la topbar. Les 78 premiers pixels sont interdits : aucun contrôle ne doit y entrer, jamais. Menu applicatif natif dans la barre de menus du système ; ⌘ dans tous les raccourcis.

décoration côté client, boutons caption dessinés · réserve 0 / 138
Les trois boutons caption sont dessinés par l'app : 46×48px chacun, glyphes Segoe Fluent, pas de bordure entre eux, angles droits. États communs aux trois variantes

Le contenu et l'ordre ne changent jamais ; seules les réserves de bord changent.
Fenêtre inactive
◧ layers main ↑8 ↓2 Push
Tout descend d'un cran : texte en text_dim, bordures à 55 %, l'accent disparaît. Aucune opacité globale.
Opération en cours
◧ layers main ↑8 ↓2 Pushing…Esc
Le fil de progression de 2px se colle sous la bordure basse de la topbar. Le détail complet vit dans la statusbar.
Fenêtre étroite — sous 1100px
◧ layers main ↑8 ↓2 ↑ ⋯
Ordre d'effondrement : libellés des actions → Fetch/Pull dans le menu ⋯ → champ de recherche réduit à son icône. Push, action la plus fréquente, reste toujours visible.
Ordre de tabulation
◧1 ←2 →3 Fetch4 Pull5 Push6 7
Tab sort ensuite vers la sidebar (cible 8). Les boutons caption Windows et les feux macOS ne sont jamais dans l'ordre de tabulation de l'app.
Réserves, pas marges
Les 78px macOS et les 138px Windows sont des zones interdites gérées par un spacer de flex, pas par un padding conditionnel. Un contrôle posé à 12px du bord gauche finirait sous les feux.
Rien n'est calé au pixel sur du texte
SF Pro, Segoe UI Variable et la police système Linux ont des métriques différentes. Tout est en flexbox : le bloc dépôt a un max-width avec ellipse, le spacer central absorbe la différence.
Un seul modificateur logique
La documentation dit ⌘/Ctrl. L'app affiche ⌘K sur macOS et Ctrl K ailleurs — jamais les deux.
